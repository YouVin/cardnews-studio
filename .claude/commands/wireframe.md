`docs/B02-ia.md`, `docs/B04-screendef.md`, `schemas/screens.schema.json` 을 읽어라.

`specs/screens.json` 을 작성한다. 스키마를 벗어나는 키를 만들지 마라.

## 규칙

- `canvas`는 모바일 웹 375x812 (PC 우선이면 1440x1024)
- `index`는 `true` — 좌측에 전체 페이지 목록 패널이 자동 생성된다
- IA의 **모든 화면**을 넣는다. 대표 화면 몇 개만 고르지 마라
- `group`은 IA의 그룹명과 정확히 일치시킨다
- `note`에는 **이 화면이 이 구조인 이유**를 한 문장으로. 여기가 이 산출물의 핵심이다

## 실제 요소를 넣어라

빈 회색 박스만 나열하면 화면을 이해할 수 없다. 화면정의서에 적은 실제 내용을 넣는다.

- `label`에는 진짜 문구를 쓴다. "버튼 영역"이 아니라 "바로 예약"
- 목록 화면은 `card` 타입을 쓰고 `meta`와 `action`을 채운다
  예: `{"type":"card","label":"대회의실","meta":["8인실","3층"],"action":"바로 예약","items":3}`
- 검색이 있으면 `searchbar`, 필터·정렬이 있으면 `chips`를 쓴다
  `chips`의 `label`은 `/`로 구분: `"필터 / 정렬 / 인원"`
- 상단 네비게이션은 `nav`, 하단 탭은 `tabbar` (tabbar는 자동으로 하단 고정)
- `table`의 `label`은 `·`로 열 제목을 구분: `"나이 · 키 · 인심"`

## 넣지 말 것

색, 폰트, 아이콘 스타일, 이미지 내용. 와이어프레임이다.

다 쓰고 화면 수(IA 대비), 스키마 검증 결과를 보고하고 멈춰라.
