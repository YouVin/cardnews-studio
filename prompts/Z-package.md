# Z. 제출용 한 장 요약

## 출력 구조 (docs/00-summary.md)

### 상단 — 한 줄 정의
```
[브랜드/제품] 카드뉴스 N장 · 기획 산출물 역구성
작업 범위: (제작 / 기획 / 둘 다) · 기간: (모르면 생략)
```

### 1. 무엇을 만들었나
완성 결과물 한 문단. 채널, 분량, 목적.
자랑하지 말고 사실만. 3문장 이내.

### 2. 어떤 판단이 있었나 (핵심 3개)
가장 설명력 있는 기획 판단 3개만 고른다. 하나당 이 형식:

**판단 —** 무엇을 어떻게 정했는가
**근거 —** 왜 그렇게 정했는가
**출처 —** `A01-brief.md 4. 타겟` 형태로 표기

3개를 고르는 기준: **"안 그랬으면 어떻게 됐을까"에 답이 나오는 것.**
"타겟을 부모로 잡았다" 같은 건 당연해서 판단이 아니다.
"팔로우가 명시 CTA지만 목적은 구매 검토로 잡았다. 카드 1~3이 전부
구매 판단 정보이므로 팔로우 목적으로는 카드 구성이 설명되지 않는다" — 이런 게 판단이다.

### 3. 스스로 발견한 문제 (3개)
결과물을 다시 뜯어보며 찾은 약점. 하나당 한 줄 + 출처.

**이 섹션이 이 문서 전체에서 가장 중요하다.**
자기 결과물의 약점을 먼저 말하는 사람은 다음 작업에서 같은 실수를 안 한다는 뜻이다.
읽는 사람이 실제로 사고 싶어 하는 건 그 능력이다.

### 4. 다음 세트에 적용할 것
3번의 문제를 실행 가능한 형태로 바꾼 것. 2~3개.
"개선하겠습니다"가 아니라 "카드 2를 둘로 쪼개고 앞에 문제 제기 카드를 넣는다" 수준.

### 5. 첨부 문서
| 파일 | 내용 | 언제 보면 되는지 |
|---|---|---|
| `A00-teardown.md` | 카드별 해부 | 왜 이 순서인지 궁금할 때 |
| ... | | |

세 번째 열이 중요하다. 다 읽으라고 하면 아무도 안 읽는다.

### 6. 제출 가이드 (문서 하단, 읽는 사람용 아님)
```
--- 이 아래는 제출 시 삭제 ---
```
이 구분선 아래에 아래를 적는다.

**추천 제출 형태**
- 슬라이드/PDF: 완성 카드뉴스 이미지와 와이어프레임을 좌우로 배치한 장을 반드시 넣는다
- 노션: 이 요약을 상단에, 나머지를 토글로 접는다
- 파일 8개를 그냥 압축해서 보내지 마라

**말할 때 순서**
1. 결과물부터 보여준다 (설명 없이)
2. "이건 이렇게 정해서 나온 결과입니다" — 판단 3개
3. "그런데 다시 보니 이게 아쉽습니다" — 문제 3개
4. "다음엔 이렇게 합니다" — 적용안

**예상 질문과 답할 지점**
문서 내용을 근거로 나올 법한 질문 3개와, 어느 문서를 펴면 되는지.
