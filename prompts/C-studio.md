# C. 피그마 스튜디오 스펙

`/studio` 가 참조하는 작성 지침. 항목을 바꾸고 싶으면 여기를 고친다.

## brief — 기획 요약

| 키 | 내용 | 출처 |
|---|---|---|
| `product` | 제품명 | A01 1. 프로젝트 개요 |
| `oneLine` | 한 줄 정의 | A01 5. 핵심 메시지 |
| `persona` | 누구에게 | A01 4. 타겟 |
| `desire` | 그들이 원하는 것 | A02 1. P.D.A. |
| `awareness` | 인식 수준 | A01 4. 타겟 |
| `coreMessage` | 다 본 사람이 기억할 한 문장 | A01 5 |
| `tone` | 말투 규칙 | A01 6. 톤 & 매너 |
| `goal` | 이 세트의 목적 | A01 3. 목표 |
| `outOfScope` | 이번에 안 다룬 것 | A01 7. 제작 범위 |

## prd — 근거

| 키 | 내용 |
|---|---|
| `background` | 왜 이 콘텐츠가 필요했는가 |
| `problems` | 타겟이 겪는 문제. 3개 이내 |
| `features` | 제품의 소구점. `no`는 `1`, `2`… |
| `success` | 목표와 측정 방법. **실측값은 넣지 않는다** |

## cards — 카드 설계

카드 흐름의 기본형:

```
후킹 → 문제 제기 → 근거 → 해법 → 신뢰 → CTA
```

**문제 제기를 건너뛰지 마라.** 안심시키려면 그 앞에 걱정이 있어야 한다.
근거 없이 스펙부터 나열하면 독자가 왜 읽어야 하는지 모른다.

| 키 | 규칙 |
|---|---|
| `role` | 위 6종 중 하나 |
| `angle` | 공감·두려움·혜택·편의·권위 중 하나 |
| `why` | 문서에서 가져온 판단. 동어반복 금지 |
| `headline` | 20자. 명사로 끝내지 말고 독자에게 말을 걸어라 |
| `sub` | 45자. 헤드라인을 설명하되 반복하지 마라 |
| `body` | 항목당 30자. 3~5개 |
| `cta` | CTA 카드에만. 나머지는 `null` |
| `layout` | cover / text / list / table / cta |

## 글자 수를 지켜야 하는 이유

피그마 프레임은 고정 크기다. 글자가 길면 잘리거나 프레임을 뚫고 나간다.
"조금 넘어도 되겠지"가 쌓이면 20장 만들었을 때 전부 다시 고쳐야 한다.
