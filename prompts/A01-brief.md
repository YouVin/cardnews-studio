# A01. 콘텐츠 기획서

소프트웨어 PRD가 아니다. **콘텐츠 기획서 / 크리에이티브 브리프**다.
용어를 섞지 마라. "요구사항", "기능", "릴리즈" 같은 말을 쓰지 않는다.

## 출력 구조 (docs/A01-brief.md)

### 1. 프로젝트 개요
| 항목 | 내용 |
|---|---|
| 프로젝트명 | |
| 클라이언트/브랜드 | |
| 채널 | |
| 분량 | 카드 N장 |
| 제작 기간 | 모르면 `-` |

### 2. 배경과 과제
이 브랜드가 지금 겪고 있는 문제. 왜 이 콘텐츠가 필요했는가.
근거 없이 시장 상황을 서술하지 마라. 결과물에서 읽어낸 것만 쓴다.

### 3. 목표
| 목표 | 측정 지표 | 실측 |
|---|---|---|
실측값을 모르면 `-`. 지어내지 마라.

### 4. 타겟
| 항목 | 내용 |
|---|---|
| 주 타겟 | |
| 상황 | 이 콘텐츠를 보게 되는 순간 |
| 인식 수준 | 무인식 / 문제인식 / 솔루션인식 / 제품인식 |
| 이 사람이 스크롤을 멈추는 이유 | |

인식 수준은 뒤에 나올 메시지 설계의 근거가 되므로 반드시 하나로 확정한다.

### 5. 핵심 메시지
한 문장. 이 세트를 다 본 사람이 기억해야 할 단 하나.

### 6. 톤 & 매너
말투, 문장 길이, 하지 않을 표현. 결과물의 실제 카피에서 역으로 뽑아낸다.

### 7. 제작 범위
**포함** — 이번에 만든 것
**제외** — 논의됐지만 안 넣은 것 + 왜 뺐는지. 모르면 이 항목을 통째로 비워라.
없는 걸 있는 척 적는 게 제일 위험하다.

### 8. 아쉬웠던 점
결과물을 다시 보며 발견한 개선 지점 2~3개.
이 항목이 문서 전체의 신뢰도를 만든다. 자기 결과물을 비평할 수 있는 사람으로 보인다.
