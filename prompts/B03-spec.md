# B03. 기능명세서 — 계층 트리

기능을 **대분류 → 중분류 → 소분류** 3단 트리로 정리한다.
번호 체계가 이 문서의 핵심이다. "2.1번 이슈"라고 부를 수 있어야 한다.

## 출력 구조 (docs/B03-spec.md)

### 1. 기능 트리 (전체 조감)
Mermaid `flowchart LR` 로 서비스 → 대분류 → 중분류까지 그린다.

```
flowchart LR
  ROOT[서비스명] --> F1[1. 대분류]
  F1 --> F11[1.1 중분류]
  F1 --> F12[1.2 중분류]
```

### 2. 기능 목록
| 번호 | 기능명 | 분류 | 설명 | 관련 화면 | 우선순위 |
|---|---|---|---|---|---|
| 1 | 워크스페이스 관리 | 대 | 조직 단위로 운영할 수 있도록 사용자와 역할을 관리한다 | S01, S02 | P0 |
| 1.1 | 조직 생성 및 멤버 초대 | 중 | | S02 | P0 |
| 1.1.1 | 초대 링크 발급 | 소 | | S02 | P1 |

번호 규칙:
- 대분류 `1`, `2`, `3`
- 중분류 `1.1`, `1.2`
- 소분류 `1.1.1`
- **번호는 절대 재사용하지 않는다.** 기능이 빠져도 번호는 비워둔다

### 3. 기능별 상세
중분류 단위로 아래를 반복한다. 소분류까지 상세를 쓰지 않는다. 문서가 늘어지기만 한다.

**1.1 조직 생성 및 멤버 초대**

| 항목 | 내용 |
|---|---|
| 목적 | 한 문장 |
| 범위 | 이 기능이 하는 것 / 하지 않는 것 |
| 선행 조건 | 이 기능을 쓰려면 먼저 무엇이 되어 있어야 하는가 |
| 동작 | 입력 → 처리 → 출력 |
| 권한 | 누가 쓸 수 있는가 |
| 관련 화면 | S02, S03 |

**여기까지가 기능명세서다.** 화면별 상태·예외·검증규칙은 화면정의서(B04)에서 다룬다.
두 문서가 같은 내용을 중복하면 나중에 한쪽만 고쳐져서 어긋난다.

### 4. 우선순위 근거
P0로 잡은 기능이 왜 P0인지. 전부 P0면 우선순위를 안 매긴 것이다.
